## 2. Ключевые находки (каждая стоила отладки)

1. **Cloudflare проверяет не только cookie, но и TLS-отпечаток клиента.** Cookie `cf_clearance`, скопированная из браузера, **не помогает** Go-программе: запрос всё равно получает challenge.
   → Решение: собственный клиент **Chrome DevTools Protocol** (`internal/rutracker/cdp.go`): приложение подключается к браузеру пользователя (`Edge --remote-debugging-port=9222`), проходит проверку Cloudflare и читает защищённые страницы **оттуда**; наша `bb_session` переносится в браузер через `Network.setCookie` (нужно сначала открыть вкладку — иначе `Network.setCookie` молча не срабатывает).
   → Побочный эффект: `go-rod` использовать нельзя — политика Code Integrity блокирует бинарники с браузерной автоматизацией (проверено), а «голый» CDP-клиент проходит.
2. **Windows не даёт переименовать открытый файл.** anacrolix пишет куски в `X.flac.part` и переименовывает в `X.flac` при завершении piece'а — но наш reader держит файл открытым → `Access is denied`, piece не завершается, поток рвётся на EOF.
   → Решение: `storage.NewFileOpts(..., UsePartFiles: false)` — запись сразу в финальный файл, без переименования.
3. **`anacrolix/torrent` требует `cfg.Seed = true`**, иначе клиент отклоняет входящие соединения («don't want conns right now») и сидер молча не отдаёт данные.
4. **Хранилище anacrolix выравнивает файлы по chunk'у (16 КБ)** — поток отдавал 27 КБ мусора за концом файла, и аудиопарсер падал с «invalid sync-code» вместо EOF. Решение: `Session.OpenFile` ограничивает поток логической длиной файла.
5. **Поиск rutracker ломается от параметра `f`:** `tracker.php?nm=X&f=NNN` → «Не найдено». Рабочий контракт: `tracker.php?nm=X` (поиск по всему сайту, раздел указан в каждой строке), а фильтр по разделу применяем у себя.
6. **Форум отдаётся в windows-1251**, а браузерный транспорт — уже в UTF-8. Перекодировать браузерный ответ нельзя — иначе русские заголовки превращаются в мусор.
7. **`\b` в Go — ASCII-граница слова**, поэтому поиск «Полная дискография» по-русски не срабатывал.
8. **WAVWriter писал PCM поверх заголовка** (WriteAt не двигал позицию файла) — WAV получался без заголовка.
9. **FLAC-декодер терял CONSTANT-субфреймы** (брал `len(Samples)` вместо `NSamples`) — тихая потеря 22 сэмплов.
10. **Smart App Control** на машине блокирует запуск новых неподписанных бинарников (включая `go test` и `compile.exe`): спасла сборка с `-ldflags "-s -w"`. Обходить политику нельзя — её снимают администратором или подписью публичным CA.
11. **Sniffer FLAC читал метаданные со сдвигом на 4 байта** — блоки метаданных начинаются сразу после сигнатуры `fLaC`, а не после 8 байт. Из-за этого sample rate, длительность и битность были мусором (длительность треков считалась неверно).
12. **Readahead anacrolix по умолчанию растёт с позиции чтения** (`CurrentPos - ContiguousReadStartPos`): чем дальше прочитали, тем шире окно приоритетов и тем больше кусов клиент качает «про запас». Для трека внутри альбома это означало скачивание **всего файла**.
    → Решение: фиксированное окно `SetReadahead(256 КБ)` в `Session.OpenFile` — пара piece'ов вперёд для ровного воспроизведения.
13. **Позиция трека внутри альбома FLAC не выражается в байтах.** Кадры FLAC сжаты, поэтому «сэмпл → байт» нелинейно: вычислить позицию трека заранее нельзя.
    → Решение: у трека из cue известна **длительность**; декодер пропускает нужное число сэмплов и **останавливается на границе трека** (`Decoder.LimitSamples`), после чего поток перестаёт читать — и торрент-клиент не качает остаток альбома.
14. **anacrolix создаёт «дырявых» соседей.** При записи piece'а, пересекающего границу файлов, он создаёт **все** затронутые файлы целиком (полного размера), но заполняет только свою часть: рядом с нужным треком появляются файлы правильного размера с дырами.
    → Решение: `Session.CleanupIncompleteFiles()` — удаляет незаполненные файлы (в начале работы с раздачей, пока их не открыл anacrolix; Windows не даёт удалять открытый файл).
15. **Прогресс загрузки нельзя считать по сетевому счётчику** (в нём есть служебный трафик и выравнивание по piece'ам) — только по реальной готовности файлов: `File.BytesCompleted()`.
16. **`oto` разрешает создать контекст звукового устройства только ОДИН раз за процесс** (иначе паника «NewContext can be called only once»). Решение: общий контекст + переиспользуемый проигрыватель; поток приводится к формату устройства (44100 Гц, стерео) простым ресемплингом.
17. **Размер и число сидов на странице темы** лежат в неочевидных местах: точные байты — в `title` у скрытого счётчика `span#tor-size-humn`, сиды/личеры — в `span.seed` / `span.leech` внутри блока «Статистика раздачи».
18. **Раздачи лежат в ПОДРАЗДЕЛАХ форума** («Rock (Hi-Res)»), а список разделов даёт родительские («Rock»). Без обхода подразделов фильтр «только музыка» отсекал всё.
    → Решение: `Client.ForumSubIDs` (страница раздела → список подразделов) с кэшем; набор id кэшируется на диске (`music-forums.json`) — первый обход ~100 с, дальше мгновенно.
19. **Поиск с «nm» и «f» одновременно ломается** («Не найдено»), а «nm» без «f» отдаёт 50 раздач всего сайта. Для страницы исполнителя это и нужно: ищем одним запросом и фильтруем по разделу у себя.

## 2.1 Окно приложения (GUI)

Приложение запускается как `rutstream gui` и открывает настоящее окно:

- **Без Node.js и сборщика.** Фронтенд — обычные HTML/CSS/JS, встроенные в бинарник через `go:embed`; окно — WebView2 (движок Edge, уже есть в Windows).
- **Локальный HTTP-сервер** на 127.0.0.1 со случайным портом и JSON-API: разделы, поиск, тема, план, воспроизведение, очередь загрузок, состояние.
- **Четыре колонки**: разделы → результаты поиска → треклист → плеер с очередью загрузок.
- **Лента раздач**: сортировка (рейтинг / сиды / размер / дата) и фильтры (lossless, «с сидами», «коллекции»), бейджи качества (FLAC 24/96, ALAC, APE, MP3 320, V0, 128).
- **Страница исполнителя**: все его раздачи, сгруппированные по альбомам (30 релизов для The Beatles), с переходом к лучшей раздаче каждого альбома.
- **Кнопки у раздачи**: «Скачать альбом» и переход к исполнителю.
- **Воспроизведение идёт потоком**: PCM пишется в звуковую карту по мере скачивания (`audio.PlayToWriter`), трек можно остановить в любой момент.
- **Прогресс** — по объёму скачанного (для обычных треков) и по времени (для треков с cue-разметкой, где длительность известна).

Проверено вживую: поиск «beatles» → 50 раздач; страница исполнителя → 30 релизов; треклист раздачи The Beatles — Rubber Soul (Super Deluxe) из 68 треков; воспроизведение трека №2 «Norwegian Wood» — 13.2 МБ из 960.8 МБ раздачи, 0 байт на SSD (режим RAM).

## 3. Режим RAM (0 байт на SSD)

Собственное хранилище в памяти (internal/torrent/memstorage.go): piece'ы не пишутся на диск,
а после проигрывания трека освобождаются (RUTSTREAM_STORAGE=ram, лимит RUTSTREAM_MEM_LIMIT_MB).

Проверено вживую на раздаче The Beatles — Rubber Soul (Super Deluxe):
26.28 МБ по сети → 199.9 с звука → **память после трека 0 Б**, на диске личера 0 файлов.

## 5. Как пользоваться сейчас

```powershell
# 0) режим хранения: disk (по умолчанию) или ram (0 байт на SSD при стриминге)
$env:RUTSTREAM_STORAGE = "ram"

# 1) один раз: запустить браузер с отладкой (нужно закрыть Edge полностью)
& "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe" --remote-debugging-port=9222

# 2) собрать и запустить
cd C:\Users\mixa7\Documents\RutStream\rutstream
& "$env:TEMP\opencode\go\bin\go.exe" build -ldflags "-s -w" -o bin\rutstream.exe ./cmd/rutstream
$env:RUTSTREAM_COOKIE = "<bb_session из DevTools>"
$env:RUTSTREAM_STORAGE = "ram"     # 0 байт на SSD при стриминге
.\bin\rutstream.exe gui             # приложение с окном
.\bin\rutstream.exe check           # диагностика доступа
.\bin\rutstream.exe search beatles  # поиск по всему сайту
.\bin\rutstream.exe show 6917156    # тема + треклист
.\bin\rutstream.exe plan 6917156    # что и сколько скачается
.\bin\rutstream.exe play 6917156 1  # потоковое воспроизведение трека №1
.\bin\rutstream.exe download 6917156 1   # скачать трек на диск
```

## 6. Что дальше

1. **Подпись приложения** (публичный CA) — иначе Smart App Control не даст запускать его на других машинах.
2. **Длительность обычных треков**: сейчас известна только для cue-раздач (берётся из cue);
   для отдельных файлов её можно брать из треклиста сайта или из STREAMINFO (ценой докачки заголовка).
3. **Ratio Guard в бою**: счётчики «скачано/раздано» по раздаче уже есть, но пока не выведены в интерфейс.
4. **Рекомендации** (исполнитель/альбом/треки): поиск по исполнителю уже есть в `rutracker.SearchArtist`,
   но в GUI пока не выведена лента «похожее».
